## P0：上线阻断项


### L-202：外部操作审批闭环未实现

- 对应需求：FR-405、AC-208。
- 现状：工具风险等级仅有 `read`、`network_read`、`code_execution`、`internal_write`，没有 `write_reversible`、`write_high_risk`，也未发现 Approval Gate、审批记录或参数 Hash 绑定。
- 证据：[types.ts:101-112](../server/domain/types.ts#L101-L112)、[ai-resource-service.ts:230](../server/application/ai-resource-service.ts#L230)、[第二期需求文档:301-305](../需求文档/第二期-需求评审与大模型配置需求文档.md#L301-L305)。
- 验收影响：无法证明高风险写操作经人工逐次确认、参数变化后审批失效、拒绝/超时/取消后停止执行。
- 收口目标：补齐风险分级、Approval 实体、审批 API/UI、参数摘要或 Hash、有效期、操作者、审批结果与运行时强制校验；拒绝、过期、取消或参数变更必须阻止执行。

### L-203：Finding 人工处置未持久化

- 对应需求：FR-205、AC-203。
- 现状：Finding 状态仅写入前端组件状态，页面已明确提示后端不存在 Finding Action 接口；数据库状态没有 Finding/Action 实体。
- 证据：[RequirementReviewPage.tsx:708-713](../src/RequirementReviewPage.tsx#L708-L713)、[types.ts:231-263](../server/domain/types.ts#L231-L263)、[第二期需求文档:201-205](../需求文档/第二期-需求评审与大模型配置需求文档.md#L201-L205)。
- 验收影响：刷新、切换运行、重新评审和导出后均无法保留处置状态、说明、操作者与历史记录；无法保证原始 Finding 不被改写。
- 收口目标：新增不可变 `FindingAction` 追加记录与 Finding 当前状态投影；提供并发控制、状态转换、说明校验、操作者与时间审计；查询、过滤与导出均从持久化结果读取。

### L-204：评审问答会话和 Turn 未持久化

- 对应需求：FR-206、AC-209。
- 现状：问答服务运行后直接返回响应，未写入问题、回答、引用 Evidence、模型实际路由、Agent/Prompt/工具版本、执行用量或失败摘要；前端对话保留在组件状态。
- 证据：[review-qa-service.ts:16-49](../server/application/review-qa-service.ts#L16-L49)、[RequirementReviewPage.tsx:750-784](../src/RequirementReviewPage.tsx#L750-L784)、[第二期需求文档:208-214](../需求文档/第二期-需求评审与大模型配置需求文档.md#L208-L214)。
- 验收影响：无法恢复历史问答、复核实际执行上下文或满足问答审计要求。
- 收口目标：新增 ReviewQaSession/ReviewQaTurn 持久化模型；每轮固定并保存 Agent、模型、Prompt、Tool/MCP/Skill、引用、执行摘要、用量与脱敏错误；发送和读取前重新校验访问权限。

### L-205：报告导出未由服务端基于正式结果生成

- 对应需求：FR-209、AC-209。
- 现状：前端直接把内存中的 Run、Finding 状态和 Evidence 拼接为 Markdown Blob 下载；不存在服务端导出接口与重新鉴权。
- 证据：[RequirementReviewPage.tsx:787-840](../src/RequirementReviewPage.tsx#L787-L840)、[第二期需求文档:228-232](../需求文档/第二期-需求评审与大模型配置需求文档.md#L228-L232)。
- 验收影响：无法证明导出只读取指定项目版本和运行的正式持久化结果，也无法统一排除候选输出、问答全文、明文凭据和未脱敏日志。
- 收口目标：提供版本和运行强作用域的服务端导出端点；导出前重新鉴权；固定报告模板与字段白名单；包含正式输入、Finding、Evidence、降级与持久化处置状态。

## P1：核心业务与运行治理缺口

### L-206：ReviewRun 未运行在独立 Worker 队列

- 对应需求：FR-202、M3 退出条件。
- 现状：创建评审 API 直接调用 `RequirementAnalysisService.start()`，运行驻留 API 进程；服务重启后仅将 `running` Run 收口为失败，未实现 Review Job、独立 Worker、租约、心跳、fencing token 或断点恢复。
- 证据：[server.ts:26-35](../server/http/server.ts#L26-L35)、[server.ts:74-78](../server/http/server.ts#L74-L78)、[第二期技术文档:75-100](第二期-需求评审与大模型配置技术文档.md#L75-L100)。
- 验收影响：无法满足服务重启、Worker 失租约和并发抢占后的恢复与晚到结果隔离要求。
- 收口目标：复用一期任务队列的 lease、heartbeat、run token 与 fencing 思路，建立 ReviewJob/ReviewWorker；所有正式发布必须验证当前 fencing token，并支持优雅停止和恢复重试。

### L-207：模型运行时重试后降级未实现

- 对应需求：FR-304、AC-205。
- 现状：启动 Run 时可从主模型和候选模型中选择一个健康模型；发生临时模型错误后，Runtime 只会对同一模型重试，未实现耗尽重试后按候选模型切换，也未记录实际降级原因。
- 证据：[requirement-analysis-service.ts:530-544](../server/application/requirement-analysis-service.ts#L530-L544)、[pi-agent-runtime.ts:225-240](../server/agent/pi-agent-runtime.ts#L225-L240)、[第二期需求文档:253-258](../需求文档/第二期-需求评审与大模型配置需求文档.md#L253-L258)。
- 验收影响：无法证明仅在允许降级且候选能力满足时切换，并展示真实模型、重试次数和降级原因。
- 收口目标：实现 SmartHub Agent 执行边界外的路由状态机：主模型调用、可重试错误、有限重试、能力复核、候选切换、调用审计与最终失败收口。

### L-208：模型检测与质量门禁不完整

- 对应需求：FR-305、FR-306、AC-206。
- 现状：模型探测仅覆盖连通性和可选工具调用，未验证长上下文理解、结构化结果质量、最小提交工具完整链路及版本化黄金样本门禁。
- 证据：[model-service.ts:87-129](../server/application/model-service.ts#L87-L129)、[第二期需求文档:260-267](../需求文档/第二期-需求评审与大模型配置需求文档.md#L260-L267)。
- 验收影响：工具调用探测通过不能证明模型适合需求提取，无法满足正式可用性必须通过黄金样本质量门禁的要求。
- 收口目标：补齐受控长上下文、结构化输出、提交工具链路探测；探测结果持久化脱敏指标；将模型、Prompt、投递策略与工具版本变更纳入质量门禁。

### L-209：稳定路由与刷新恢复未实现

- 对应需求：FR-207、FR-209、AC-209。
- 现状：未发现 URL 或等价路由状态持久化 `projectVersionId`、`reviewId`、`runId`、当前视图及可选 Finding/Evidence；页面状态主要位于 React 内存状态。
- 证据：[第二期需求文档:216-220](../需求文档/第二期-需求评审与大模型配置需求文档.md#L216-L220)、[第二期需求文档:228-232](../需求文档/第二期-需求评审与大模型配置需求文档.md#L228-L232)。
- 验收影响：刷新、分享链接或浏览器前进/后退后无法可靠恢复指定项目版本与历史运行，也无法证明不同运行数据不串用。
- 收口目标：定义并实现稳定 URL 路由；前端切换版本或运行时取消旧请求、清空旧视图并按显式 `projectVersionId + reviewId + runId` 重新加载；缺失或无权限时返回明确错误。

## P1：文档与领域契约待统一

### L-210：Finding 严重度枚举不一致

- 需求文档定义：`blocker`、`high`、`medium`、`low`。
- 技术文档与前端实现定义：`critical`、`high`、`medium`、`low`、`info`。
- 证据：[第二期需求文档:183](../需求文档/第二期-需求评审与大模型配置需求文档.md#L183)、[RequirementReviewPage.tsx:48](../src/RequirementReviewPage.tsx#L48)。
- 影响：API Schema、模型输出校验、筛选、统计、导出与历史数据迁移没有统一契约。
- 收口目标：由产品、技术和测试共同确认唯一领域枚举；同步需求文档、技术文档、数据库迁移、服务端 Schema、前端展示及验收用例。

### L-211：Finding 状态与动作模型存在分叉

- 需求文档状态：`open`、`confirmed`、`dismissed`、`resolved`、`needs_follow_up`。
- 技术文档 ADR-208 动作示例：接受、驳回、转任务、已处理、重新打开。
- 证据：[第二期需求文档:201-205](../需求文档/第二期-需求评审与大模型配置需求文档.md#L201-L205)、[第二期技术文档:216-219](第二期-需求评审与大模型配置技术文档.md#L216-L219)、[RequirementReviewPage.tsx:37](../src/RequirementReviewPage.tsx#L37)。
- 影响：FindingAction 数据模型、状态机、UI 操作、审计与迁移规则无法稳定设计。
- 收口目标：明确“不可变动作事件”和“当前状态投影”的映射关系，并确定是否支持转任务、重新打开及其状态转换约束。



## 已验证完成的基础能力

以下能力已有代码与自动化测试证据，不作为本遗留文档的阻塞项：

1. 项目版本强隔离及全部有效需求绑定校验。
2. Run 快照固定资产版本、内容 Hash、索引、模型、Agent 和输入投递计划。
3. 提取 Agent 与评审 Agent 的独立会话、服务端校验、冻结交接与仅评审重跑。
4. 正常规模正文 `full_context` 直传、超长内容 `segmented_context` 确定性分批和最终归并。
5. 服务端生成 InputDeliveryManifest、Evidence 规范化与固定版本定位。
6. 基础取消、失败状态和受控 Tool/Skill/MCP 调用能力。
